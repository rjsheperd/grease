#+AUTHOR: Adrian Smith
#+OPTIONS: toc:2

Run Clojure on iOS using GraalVM native-image and JDK 21 static libraries.
Includes a live SCI nREPL on-device for interactive development.

For the latest discussion, see the [[https://clojurians.slack.com/archives/C0260KHN0Q0][#graalvm-mobile]] channel on Clojurians Slack.

* Architecture

The build pipeline has three stages:

1. *ios-graal-jdk-21* — builds =libjava.a= and =libjvm.a= as iOS arm64 static
   libraries from a patched labsJDK 21 and GraalVM SubstrateVM.

2. *Clojure → bb.o* — compiles the Clojure source to an uberjar, then runs
   =native-image= (Gluon GraalVM) to produce =bb.o= and =bb.h=.

3. *MobileTest.app* — links =bb.o= with the JDK static libs inside the Xcode
   project, then signs and installs on a connected device.

* Prerequisites

** Xcode 14.3.1

Required for the iOS 16.4 SDK and reproducible builds. Pin the system once:

#+begin_src bash
sudo xcode-select -s /Volumes/MegaDisk2TB/XCode/AF56C562-4191-470B-AECA-8CBE68A2E188/Xcode.app
#+end_src

The nix dev shell will warn if this is not set correctly.

** Gluon GraalVM

Provides =native-image= with iOS arm64 support. Not available in nixpkgs;
download from [[https://github.com/gluonhq/graal/releases]] and unpack under
=graal/= in this directory:

#+begin_src bash
# After unpacking, ~/.graal/latest should point at Contents/Home
export JAVA_HOME=$HOME/.graal/latest/Contents/Home
export GRAALVM_HOME=$JAVA_HOME
#+end_src

** ios-graal-jdk-21

Sibling repository that builds the JDK static libs. Clone adjacent to this repo:

#+begin_src bash
git clone https://github.com/rjsheperd/ios-graal-jdk-21 ../ios-graal-jdk-21
#+end_src

** ios-deploy

Installs the signed =.app= on a connected device:

#+begin_src bash
brew install ios-deploy
#+end_src

** Nix dev shell

Provides =clojure=, =autoconf=, and =fastlane= with a compatible Ruby:

#+begin_src bash
nix develop
#+end_src

* Build

** Step 1: Build JDK static libraries

From the =ios-graal-jdk-21= sibling directory:

#+begin_src bash
cd ../ios-graal-jdk-21
./build.sh
#+end_src

Outputs: =build/ios-arm64/lib/libjava.a= and =build/ios-arm64/lib/libjvm.a=.

** Step 2: Build bb.o (Clojure → native-image)

#+begin_src bash
./scripts/build-bb-o
#+end_src

Outputs: =build/bb/bb.o= and =build/bb/bb.h=.

For a fully clean build (clears all caches):

#+begin_src bash
rm -rf build/bb build/bb-tmp target conf/capcache
./scripts/build-bb-o
#+end_src

Subsequent builds are faster with the CAPCache:

#+begin_src bash
USE_CAP_CACHE=use ./scripts/build-bb-o
#+end_src

** Step 3: Build MobileTest.app

#+begin_src bash
direnv exec . ./scripts/build-demo-app
#+end_src

Builds =MobileTest.app= in Xcode DerivedData using the static libs and =bb.o=
from the previous step. The =direnv exec .= ensures =DEVELOPMENT_TEAM= and
other signing variables from =.envrc= are present.

** Step 4: Sign and install on device

#+begin_src bash
pkill -f ios-deploy 2>/dev/null   # kill any stale process first
./scripts/deploy-demo-app
#+end_src

Signs the app with your "Apple Development" certificate and installs it on the
connected device via =ios-deploy=.

Signing uses =codesign= directly (not xcodebuild) because Xcode 14.3.1 cannot
find provisioning profiles installed by Xcode 16+.

** Step 5: Start the app and nREPL

#+begin_src bash
./scripts/debug-demo-app --noinstall
#+end_src

Attaches =lldb= to the installed app. The app starts and prints its IP and
nREPL port to the console. Default: port =23456=.

* Configuration

Sensitive per-developer values live in =.envrc= (loaded by [[https://direnv.net/][direnv]]):

| Variable             | Description                                    |
|----------------------+------------------------------------------------|
| =XCODE_DEVELOPER_DIR=  | Path to Xcode 14.3.1 =Contents/Developer=      |
| =DEVELOPMENT_TEAM=     | Apple Developer team ID                        |
| =DEVICE_UDID=          | Connected device UDID                          |
| =CERT_HASH=            | SHA-1 of your "Apple Development" certificate |
| =PROFILE_UUID=         | UUID of the provisioning profile               |
| =APPLE_KEY_ID=         | App Store Connect API key ID                   |
| =APPLE_ISSUER_ID=      | App Store Connect issuer ID                    |
| =APPLE_SECRET_PATH=    | Path to the =.p8= API key file                 |

Find your certificate SHA-1:

#+begin_src bash
security find-identity -v -p codesigning | grep "Apple Development"
#+end_src

* Provisioning

[[https://fastlane.tools/][fastlane]] manages device registration and provisioning profiles via the
App Store Connect API.

#+begin_src bash
cd fastlane
# Register a new device
fastlane register_device udid:"<UDID>" name:"My iPhone"
# Download/refresh the development provisioning profile
fastlane sigh --development
#+end_src

The =fastlane/Fastfile= reads credentials from the environment variables in
=.envrc=.

* Simulator builds

Three scripts provide a self-contained simulator workflow that does not require
a physical device, a signing certificate, or =ios-deploy=.

** Step 1: Patch static libs for the simulator

The iOS arm64 static libraries carry an =iphoneos= Mach-O platform tag.  The
iOS Simulator linker rejects these.  =patch-libs-for-sim= re-tags every =.o=
member to =iossim= using =vtool=, with a binary fallback for objects whose
Mach-O header has no room for the larger =LC_BUILD_VERSION= load command.

#+begin_src bash
./scripts/patch-libs-for-sim
#+end_src

Inputs: =lib/ios-arm64/*.a=, =build/staticjdk-ios-jdk21/lib/static/*.a=,
and =xcode/MobileTest/aarch64-apple-ios/.libs/libffi.a=.

Outputs: =lib/ios-sim-arm64/= and =build/staticjdk-iossim-jdk21/lib/static/=.

This step is incremental: each archive is skipped if the destination is already
newer than the source.

** Step 2: Build MobileTest for the simulator

#+begin_src bash
./scripts/build-demo-app-sim
#+end_src

Writes =build/demo-app-sim.xcconfig= and invokes =xcodebuild= with
=SDKROOT=iphonesimulator= and =ARCHS=arm64=.  DerivedData lands in
=build/DerivedData-sim= so device and simulator builds share no state.

Environment variables:

| Variable             | Default    | Description                         |
|----------------------+------------+-------------------------------------|
| =SIM_NAME=           | iPhone 16  | Simulator device name               |
| =IOS_TARGET=         | 16.0       | iOS deployment target               |
| =CONFIGURATION=      | Debug      | =Debug= or =Release=                |
| =XCODE_DEVELOPER_DIR=| xcode-select -p | Xcode developer directory      |

** Step 3: Run on the simulator

#+begin_src bash
./scripts/sim-run
#+end_src

Boots the named simulator (=xcrun simctl boot=), installs the =.app=,
streams the process log, launches the app, and polls =localhost:23456= until
the babashka nREPL is ready (up to 60 s).

Once the nREPL is open, connect from the host:

#+begin_src bash
clj -Sdeps '{:deps {nrepl/nrepl {:mvn/version "1.3.0"}}}' \
    -M -m nrepl.cmdline --connect --host localhost --port 23456
#+end_src

Or run the full integration test suite against the simulator:

#+begin_src bash
NREPL_HOST=localhost NREPL_PORT=23456 tests/run_tests
#+end_src

** Notes on the simulator linker

On Apple Silicon with CommandLineTools installed, the macOS linker searches the
CommandLineTools =MacOSX.sdk= even when =-isysroot= points at the
iPhoneSimulator SDK, picking up macOS-tagged =libobjc.tbd= and =libSystem.tbd=
before the correct simulator stubs.  =build-demo-app-sim= works around this by
copying all 143 TBD stubs from the simulator SDK's =usr/lib= into
=build/sim-sys-stubs/= and placing that directory first in
=LIBRARY_SEARCH_PATHS=, so the simulator-tagged versions are found first.

System libraries (=-lz -ldl -lstdc++ -lpthread=) are intentionally omitted
from =OTHER_LDFLAGS= in the simulator build; they are re-exported by
=libSystem= in the iPhoneSimulator SDK and resolving them explicitly would
pull in the macOS CommandLineTools versions.

* nREPL

After the app is running, connect from the host machine.

*Physical device* (IP printed to console when the app starts):

#+begin_src bash
clj -Sdeps '{:deps {nrepl/nrepl {:mvn/version "1.3.0"}}}' \
  -M -m nrepl.cmdline --connect --host 192.168.0.111 --port 23456
#+end_src

*iOS Simulator* (port forwarded automatically to localhost):

#+begin_src bash
clj -Sdeps '{:deps {nrepl/nrepl {:mvn/version "1.3.0"}}}' \
  -M -m nrepl.cmdline --connect --host localhost --port 23456
#+end_src

The nREPL runs under babashka SCI, not standard JVM Clojure.

* ObjC Interop

The =grease.ios.objc= namespace is pre-loaded at app startup and provides:

- =defclass= — registers a new ObjC class backed by Clojure fns
- =new-instance= — allocates an instance of a =defclass='d class
- =msg-send= — sends an ObjC message via =objc_msgSend=

** msg-send

The =objcjure/objc= macro works for most message sends but fails in the SCI
nREPL for selectors with trailing colons (e.g. =setDelegate:=) because SCI's
reader rejects symbols containing colons. Use =msg-send= instead:

#+begin_src clojure
(require '[grease.ios.objc :as objc-rt])

(objc-rt/msg-send :void mgr "setDelegate:" :pointer d)
(objc-rt/msg-send :void mgr "startUpdatingLocation")
#+end_src

** defclass

Define a new ObjC class at runtime with a flat sequence of
selector / type-encoding / fn triples. The class pointer is bound to the given
symbol. All objects must be retained in atoms to prevent ARC release.

#+begin_src clojure
(objc-rt/defclass LocationDelegate "NSObject"
  "locationManager:didUpdateLocations:" "v@:@@"
  (fn [_self _cmd _mgr locs]
    (reset! last-location locs)))
#+end_src

Type encoding: =v= void, =@= id/object, =:= SEL, =q= long long, =i= int.

** CLLocationManager example

#+begin_src clojure
(require '[grease.ios.objc :as objc-rt])
(require '[com.phronemophobic.grease :as grease])

(def held-mgr      (atom nil))
(def held-delegate (atom nil))
(def last-location (atom nil))

(objc-rt/defclass LocationDelegate "NSObject"
  "locationManager:didUpdateLocations:" "v@:@@"
  (fn [_self _cmd _mgr locs]
    (reset! last-location locs)))

(defn start-location-updates! []
  (grease/dispatch-main-async
   (fn []
     (let [cls-mgr (grease/get-objc-class "CLLocationManager")
           mgr     (grease/objc-new cls-mgr)
           d       (objc-rt/new-instance LocationDelegate)]
       (reset! held-mgr mgr)
       (reset! held-delegate d)
       (objc-rt/msg-send :void mgr "setDelegate:" :pointer d)
       (objc-rt/msg-send :void mgr "requestWhenInUseAuthorization")
       (objc-rt/msg-send :void mgr "startUpdatingLocation")))))

;; From the nREPL — tap Allow on the device, then check:
;; @last-location  ;; => {:address 0x...}
#+end_src

Full runnable version with error capture: =dev/test_location.clj=.

* Notes

The key ingredients for iOS static binaries:

- *JDK static libs* built for =iphoneos= arm64 (provided by =ios-graal-jdk-21=)
- *SubstrateVM libs* built for =iphoneos= arm64 (also =ios-graal-jdk-21=)
- *Gluon GraalVM* =native-image= with iOS arm64 backend
- *GraalVM reflection/resource configs* under =conf/=
